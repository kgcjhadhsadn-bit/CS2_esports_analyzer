# P9 - Betclic bet-placement executor (cs2bot.executor)

> Work-package brief: the requirements this package was built against. Keep it in sync when scope changes.

**Owned paths:** src/cs2bot/executor/, config/betclic_selectors.yaml, tests/executor/

**Tests:** tests/executor/

## Requirements

Goal: place single pre-match bets on the owner's own Betclic.pl account from the owner's Windows PC, with a VISIBLE browser using a dedicated persistent profile. The owner logs in by hand once (incl. SMS/2FA); the session is reused; when it expires the executor reports LOGIN_REQUIRED (the caller pauses the bot and the dashboard asks the owner to log in again). The Betclic DOM cannot be inspected from here (geo-blocked), so every selector lives in config/betclic_selectors.yaml with several fallbacks per element (CSS, role/text locators with Polish texts such as "Zaloguj się", "Postaw zakład", "Moje zakłady", "Kupon", "Wyczyść"), and the code must fail safe and loud when selectors don't resolve. Do not implement anti-detection/stealth tricks (no fingerprint spoofing, no stealth plugins, no CAPTCHA solving); behave like a careful human: moderate random delays between actions, low frequency.

1. Contracts: BetExecutor protocol (place(order: BetOrder) -> PlacementResult, get_balance() -> Decimal | None, health_check() -> ExecutorHealth, close()); FakeExecutor (scripted results, records calls) for tests and integration.
2. Selectors: SelectorSet loaded from YAML (pydantic-validated), each logical element -> an ordered list of locator specs ({css: ...} | {role: ..., name: ...} | {text: ...} | {xpath: ...}); a resolve(page, key, timeout) helper trying them in order; the YAML documents each element and how to update it with the browser's DevTools. Write the initial YAML with best-guess selectors for Betclic's Angular site (research what you can; mark unverified ones).
3. BetclicExecutor(settings: Settings, *, selectors: SelectorSet | None = None, halt_check: Callable[[], tuple[bool, str | None]], playwright_factory=None, sleep=time.sleep): Playwright sync API launch_persistent_context(user_data_dir=settings.betclic.browser_profile_dir, headless=settings.executor.headless, executable_path=settings.betclic.chromium_executable, locale="pl-PL", timezone_id="Europe/Warsaw", proxy from settings.betclic.proxy_url if set, a sensible viewport). Guard the profile with a cross-platform lock file (create exclusively; store PID + timestamp; stale after a configurable age) so two processes never open the same profile.
   - open_login_window(timeout_s=600) -> bool: opens the visible browser on the Betclic login page and waits until a logged-in indicator appears (the owner logs in by hand). If settings.betclic.credentials_source is "env" or "keyring" (keyring service settings.betclic.keyring_service; import keyring lazily), pre-fill username/password but never automate 2FA. Never log credentials.
   - is_logged_in() -> bool.
   - place(order): (1) halt_check() -> KILL_SWITCH result if halted; (2) ensure logged in, else LOGIN_REQUIRED; (3) open order.event_url (or locate the event by external id via the listing/search if there is no URL); (4) clear any existing bet-slip selections first; (5) find the market by raw name (and/or external-id data attributes) and the selection by raw name (normalised text match; ambiguity -> SELECTOR_ERROR, never guess); (6) read the displayed odds (Polish decimals "1,85"); if < order.min_acceptable_odds -> ODDS_MOVED; (7) click the selection and verify the slip contains exactly that one selection with matching odds; (8) enter the stake formatted Polish-style ("12,50") and verify the field value; (9) dry_run -> screenshot, clear the slip, DRY_RUN_OK (never click the final button); (10) halt_check() again immediately before confirming; (11) click "Postaw zakład", handle the odds-changed dialog (accept only if the new odds >= min_acceptable_odds, else cancel -> ODDS_MOVED), wait for the confirmation/receipt, parse the Betclic bet id and the new balance when shown -> PLACED; known error messages (insufficient balance, market suspended, stake limits) -> the matching status; if the place click happened but neither a confirmation nor an error could be detected -> UNCERTAIN (never retry automatically; the caller reconciles via bet history). Screenshot every attempt into settings.executor.screenshot_dir (file name includes bet_id + idempotency key + status); random delays between actions (settings.executor.action_delay_min_s..max_s); navigation timeouts from settings.
   - get_balance() parses the header balance ("1 234,56 zł" -> Decimal("1234.56")).
   - fetch_bet_history(since: datetime) -> list[BookmakerBetRecord] from "Moje zakłady" (bet id, placed_at, event/market/selection text, odds, stake, status open/won/lost/void/cashout, payout) for reconciliation and settlement (best effort, selector-driven).
   - health_check(): browser starts, logged-in state, balance readable, key selectors resolvable on the CS2 listing page -> ExecutorHealth.
4. Utilities: parse_polish_decimal, format_polish_decimal, normalise_text for matching (casefold, accents, whitespace), screenshot naming.
5. Tests: unit tests for parsing/formatting/selectors/lock; browser tests (mark browser; executable_path "/opt/pw-browsers/chromium"; temp profile dir) against a local mock "Betclic-like" site you write (HTML + small JS) reproducing: logged-in/out header, an event page with several markets/selections and odds, a bet slip with a stake input and place button, a confirmation with a bet id, an odds-changed dialog, an insufficient-balance error, a suspended market. Cover: dry run (the final button is never clicked - assert via the mock), successful placement, odds moved before the click and via the dialog (accept/decline), market or selection missing, ambiguous selection, login required, halt switched on between steps, no confirmation -> UNCERTAIN, stale slip cleared, stake formatting verified, screenshots written. Serve the mock via page.route or a local http.server on 127.0.0.1 (no internet).

## Review focus

SAFETY: a bet must never be placed twice (idempotency; UNCERTAIN outcomes are never retried automatically), never placed when the halt check reports halted (checked again right before the final click), never at odds below min_acceptable_odds (including via odds-change dialogs), never with a stale bet slip containing other selections, the stake text must exactly equal the order stake, dry-run must never click the final place button; plus robustness of selectors, timeouts, screenshots, the profile lock, and that credentials are never logged.

_This package gets two independent review rounds._
