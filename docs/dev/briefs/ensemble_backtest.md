# P7b - Map-win ensemble, calibration, walk-forward backtest (cs2bot.models.ensemble, cs2bot.models.calibration, cs2bot.backtest)

> Work-package brief: the requirements this package was built against. Keep it in sync when scope changes.

**Owned paths:** src/cs2bot/models/ensemble.py, src/cs2bot/models/calibration.py, src/cs2bot/backtest/, tests/learning/ (add new test files; do not rewrite your predecessor's tests), and - only to fix genuine bugs or add small helpers you need - src/cs2bot/datasets/ and src/cs2bot/features/ (built just before you in this same chain)

**Tests:** tests/learning/

## Requirements

1. calibration.py: IsotonicCalibrator and PlattCalibrator (fit(p, y), transform(p), save/load) with clipping to [eps, 1-eps]; metrics: brier(y, p), log_loss(y, p), ece(y, p, n_bins=10, strategy="uniform"|"quantile"), reliability_table(y, p, n_bins) -> list of bins (mean predicted, observed rate, count, Wilson CI), sharpness; calibration_report(y, p) -> dict.
2. ensemble.py: MapWinEnsemble(config) combining (a) the rating provider's probability (the Protocol defined in cs2bot.features; cs2bot.models.ratings.MapRatingModel, built in parallel, satisfies it - import it lazily if it exists, otherwise accept any provider), and (b) a LightGBM binary classifier trained on cs2bot.features training rows (monotone increasing constraint on the rating-logit feature; early stopping on a chronological validation split; regularisation suitable for small data), stacked by a logistic regression on out-of-fold predictions produced with expanding-window time-series CV, then isotonic-calibrated on the latest holdout window (settings.models.calibration_holdout_days). Uncertainty: sigma = sqrt(sigma_rating_part^2 + sigma_model^2) where sigma_model is the std across a small bootstrap ensemble of LightGBM models (e.g. 5) and sigma_rating_part propagates the rating model's sigma through the stacker; floor at settings.models.sigma_floor. fit(map_results, *, store, rating_provider) -> FitReport (holdout log-loss, Brier, ECE vs the rating model alone); predict(features_or_ctx, map_name, *, as_of, ...) -> MapWinEstimate (components: rating, lgbm, stacked, calibrated); feature importance; save(path)/load(path) recording model version, feature list and training window. Degrade gracefully: too little data -> fall back to the rating provider with a flag in components.
3. cs2bot.backtest: a walk-forward engine. Inputs: chronological map/match records with outcomes, historical odds (an OddsHistory protocol: quotes_before(match_id, t) and closing quote), a model trainer callable (train on data strictly before t, retrain every N days), a pricer callable(prediction-or-estimate, quote) -> OutcomeProbability, a decision callable and a staking callable (defaults: a simple threshold decision on p/EV with the Polish 12% stake tax and fractional-Kelly staking - injectable so the real cs2bot.engine functions, built in parallel, can be plugged in later). Settle bets with actual outcomes (win/lose/push/void) and track bankroll over time. Metrics: number of bets, hit rate, ROI/yield, profit curve, max drawdown (abs and %), Brier/log-loss of all predictions and of accepted bets, calibration report, average CLV ((bet odds / closing odds) - 1), per-market and per-month breakdowns. BacktestReport (pydantic) + to_markdown(). Strictly leakage-free: assert in code (and test) that training data timestamps are < prediction time and that features use as_of. Also run_synthetic_backtest(universe, ...) using cs2bot.testing.synthetic (true probabilities + synthetic_two_way_odds) so the owner can sanity-check the whole pipeline.
4. Tests: calibrators fix a deliberately miscalibrated predictor (ECE drops); metrics vs known values; the ensemble on the synthetic universe beats the 0.5 baseline and is not worse than the rating provider alone beyond noise; sigma > 0 and larger for teams with little data; save/load round-trip; graceful fallback; backtest: an oracle model (true probabilities) + noisy margin odds -> positive ROI and positive CLV; a random model -> negative ROI; a leakage guard test (a cheating trainer is detected/blocked); push/void settlement; report rendering.
