# P12 - Integration: services, jobs, `cs2bot up`, CLI, end-to-end test

**Owned paths:** the whole repository. You run alone (no other engineer is active), so you may edit any file: `src/cs2bot/services/`, `src/cs2bot/flows/`, `src/cs2bot/cli.py`, tests under `tests/services/`, and - where wiring reveals a bug or a missing hook - foundation files and other packages (keep such changes small, add a test, and note them in your report). Dependencies may only be added with `uv add` if truly unavoidable.

**Tests:** tests/services/

## Requirements

Read every file in docs/dev/reports/ first: they document each package's public API, known limitations and open "foundation change requests". Apply the open requests that are sensible; list the ones you reject and why.

1. `services/registry.py` - model lifecycle. `train_models(session, settings, *, as_of=None) -> TrainReport`: load records via `cs2bot.datasets`, fit `MapRatingModel`, `VetoModel`, `RoundModel`, `PlayerKillModel` and (when there is enough data) `MapWinEnsemble`; save artifacts under `settings.models.artifacts_dir/<version>/` and record a `model_runs` row with metrics. `load_latest(settings) -> ModelBundle | None`. Thread-safe swap of the active bundle after the nightly retrain. Never train on data after `as_of`.
2. `services/prediction.py` - `predict_match(session, match_id, bundle, settings, *, analyzer=None, now=None) -> MatchPrediction | None`: `datasets.load_match_context`, data completeness, context flags (`cs2bot.llm`: stored flags, analysis when enabled, `combine_flags`), per-map estimates for every map still possible (ensemble when fitted, else ratings), veto distribution (known steps condition it), `build_match_prediction`; persist `match_analyses` (payload + rationale, `is_latest` handling) and one `predictions` row per quoted outcome (`odds.latest_quotes` + `engine.pricing`). `predict_upcoming(...)` for all in-scope matches inside the betting window; skip matches without both teams or lineups; re-predict when the veto, lineup, flags or model version changed.
3. `services/betting.py` - `run_betting_cycle(session_factory, settings, executor, bundle, *, now=None) -> BettingReport`. For each match with a fresh prediction and fresh quotes: price -> `ev.price` -> `decision.evaluate` -> `bankroll.size_stake`; persist `bet_decisions` (accepted ones and the reasons for rejected ones); never back two selections of the same market; take outcomes in descending EV while the per-match exposure cap allows. For each accepted stake: create the `bets` row (PENDING, deterministic idempotency key from match + spec + selection) and COMMIT before calling `executor.place`; then map the result with `domain.betting.bet_status_after_placement`, write ledger entries (`engine.ledger`), store odds/bet id/screenshot. LOGIN_REQUIRED or SELECTOR_ERROR -> pause trading (`db.state.set_paused`) with a clear reason so the dashboard shows it; UNCERTAIN -> keep PLACING (counts as exposure), never retry. Check `db.state.is_trading_halted` before every placement and `bankroll.check_loss_limits` every cycle. Dry-run bets are recorded (status DRY_RUN) but never touch the ledger or the limits. A crash at any point must not lead to a double bet on restart (test it).
4. `services/settlement.py` - `settle_bets(session_factory, settings, executor=None, *, now=None) -> SettlementReport`: reconcile PLACING bets against `executor.fetch_bet_history` (found -> PLACED with its id; still absent after a grace period -> FAILED, exposure released, flagged for the owner); settle PLACED bets of finished matches: the bookmaker's own history is the source of truth for money when the bet is found there, otherwise `engine.settlement.resolve_outcome(load_match_actuals(...))`; UNKNOWN stays open and is flagged; disagreement between bookmaker and local resolver is recorded as an alert, bookmaker wins. Ledger payout/refund, pnl, closing odds (`odds.closing_odds`) and CLV, balance reconciliation via `executor.get_balance` + `ledger.reconcile`. Dry-run bets are settled "on paper" (pnl stored on the bet, no ledger) so paper performance is visible. Store executor health in `system_state["executor_health"]`.
5. `services/ingestion.py` - thin job functions around the ingest packages: PandaScore upcoming/past sync, HLTV upcoming/results/match/rankings/news sync, news triage (llm), demo processing, aggregates + role inference, scope refresh, backfill since a date (resumable, slow, polite). The HLTV fetcher and the odds browser use Playwright: keep each inside ONE thread (the scheduler lane or `flows.worker.ThreadWorker`).
6. `flows/jobs.py` - `build_jobs(...) -> list[Job]` for `flows.scheduler.Scheduler` with intervals from `settings.scheduler`: fast lane (odds collect -> predict -> bet -> settle), slow lane (ingestion, news, demos, nightly retrain as `Daily`). A failing job must never stop the others. `flows/supervisor.py` - `run_up(settings)`: check DB reachable + migrations at head, load or train models, start the executor (`executor.create_betclic_executor`, lazily; FakeExecutor never in production), the scheduler and the API (`api.create_app` with `login_launcher`, `executor_health_provider`, `scheduler_status_provider`, `event_remapper`), print the dashboard URL, shut everything down cleanly on Ctrl+C (must work on Windows: no POSIX-only signals).
7. `cli.py` - every command in the CLI table of docs/ARCHITECTURE.md (`up`, `doctor`, `db ...`, `ingest ...` incl. `hltv-browser`, `demos process`, `odds collect/unmapped`, `models train/tune`, `predict upcoming/match`, `bet run [--dry-run]`, `settle`, `backtest`, `executor login/health/balance`, `control kill-switch/pause/resume`). Thin commands calling services; helpful errors when a token/key is missing. `cs2bot doctor` checks: DB, migrations, Chromium, PandaScore token, Anthropic key, archive tool for .rar demos, disk space, config files present, dry-run state.
8. Tests (tests/services/, no network, FakeExecutor, synthetic universe via `cs2bot.testing.synthetic`): a full end-to-end test - populate history, add upcoming matches with linked Betclic events/markets/odds, train, predict, run the betting cycle (dry-run and "live" with the fake executor), write the results, settle - asserting ledger arithmetic, statuses, CLV, idempotency (two cycles -> no duplicates; crash between commit and placement -> no double bet), kill switch and pause respected, loss-limit pause, LOGIN_REQUIRED pause, UNCERTAIN handling, per-match exposure cap. CLI smoke tests (typer CliRunner). Scheduler job wiring test. `run_up` start/stop smoke test with fakes. The whole suite (`.venv/bin/python -m pytest tests -q -n 2`) must pass, plus ruff and mypy for the whole repo.
9. Docs: bring docs/ARCHITECTURE.md in line with what exists (signatures that changed, new modules), update docs/dev/STATUS.md, write docs/dev/reports/integration.md.
