# Cloud deploy: Polish VPS, Docker Compose, HTTPS, backups

**Owned paths:** `deploy/linux/` (create), `Dockerfile` (+ `.dockerignore`), `docker-compose.cloud.yml`, `Caddyfile` (or `deploy/linux/Caddyfile`), `docs/VPS_SETUP.md`, `.github/workflows/`. ONE other engineer (cloud_autonomy) edits everything else at the same time - do not edit Python code, config.py, other docs or the dashboard; list needed changes in your report.

**Tests:** validation commands (no Python tests needed): `docker compose -f docker-compose.cloud.yml config`, `bash -n` on every script, YAML parses, `hadolint`-style care by hand. Docker's daemon is not running on this machine, so you cannot build the image: be meticulous.

## Context

PLAN.md section 0 / 0b: the bot runs on ONE Linux VPS in Poland (e.g. Ubuntu 24.04 LTS at OVH / a Polish provider in Warsaw), fully autonomous, no human interaction. Read docs/dev/reports/integration.md and docs/dev/reports/ops.md (the Windows install, which stays as an alternative) and docs/ARCHITECTURE.md (CLI names).

## Requirements

1. **Dockerfile** for the app: Python 3.12 slim (or the official Playwright Python image pinned to the version in uv.lock), `uv` with the locked dependencies (`uv sync --frozen --no-dev`), Playwright Chromium + its system deps, Xvfb (headful browser on a virtual display - less bot-like than headless), `unar`/`bsdtar` for demo archives, the built dashboard (multi-stage: node build of `dashboard/` -> copy `dist`), a non-root user, `tini` as PID 1, healthcheck hitting `/api/health`, entrypoint that runs `cs2bot db upgrade` then `cs2bot up` under `xvfb-run` (or a supervised Xvfb). Persistent volumes: `data/` (browser profiles incl. the Betclic session + placement journal, models, caches, screenshots), `logs/`.
2. **docker-compose.cloud.yml**: `postgres:16` (pinned minor, volume, healthcheck, not published to the internet), `app` (depends_on healthy postgres, `restart: unless-stopped`, env from `.env`, API bound inside the network only), `caddy` (automatic HTTPS for a domain from `.env`, or a self-signed/IP fallback; basic auth or the app's own password; only 80/443 published), optional `backup` service or cron script. Log rotation (docker json-file limits). Time zone + NTP note.
3. **deploy/linux/** scripts (bash, `set -euo pipefail`, idempotent): `provision.sh` (fresh Ubuntu: updates, unattended-upgrades, ufw allowing 22/80/443 only, fail2ban, swap if RAM < 8 GB, Docker Engine + compose plugin, a `cs2bot` user, clone/pull the repo, create `.env` from `.env.example` with `chmod 600`, generate `CS2BOT_API__PASSWORD` / `SESSION_SECRET`), `deploy.sh` (pull, build, `docker compose up -d`, wait healthy, show status), `backup.sh` (pg_dump compressed, retention, optional off-site via rclone if configured), `restore.sh` (with confirmation), `update.sh`, `logs.sh`, `status.sh`, and a systemd unit or cron entries for backups + a weekly `docker system prune`. `.env` must set `CS2BOT_API__HOST=0.0.0.0` inside the container (the config requires a password then - make sure the generated one is set) and `CS2BOT_EXECUTOR__HEADLESS=false` with `DISPLAY` from Xvfb.
4. **docs/VPS_SETUP.md** for a non-developer: choosing a VPS in Poland (Warsaw region; at least 4 vCPU / 8 GB RAM / 200 GB disk for demos; rough monthly cost), SSH key setup, running provision + deploy, filling `.env` (PandaScore token, Anthropic key, Betclic username/password with `CREDENTIALS_SOURCE=env`, Telegram bot token + chat id via @BotFather and @userinfobot, bankroll and limits, `DRY_RUN`), domain + HTTPS, first start, checking Telegram, the dry-run smoke test and going live, the Betclic IP caveat (datacenter IPs may be blocked even in Poland -> `CS2BOT_BETCLIC__PROXY_URL` with a Polish residential proxy), what happens if Betclic asks for an SMS code (bot pauses + Telegram alert; log in once via the dashboard's login button / VNC-over-SSH tunnel if needed - document an `x11vnc`-over-SSH-tunnel way to see the server's browser, never exposed publicly), backups/restore, updates, costs, troubleshooting. Honest risk section (Betclic ToS forbids bots; account and balance at risk; no system wins every bet; 18+).
5. **CI** (`.github/workflows/`): add a job that builds the Docker image (no push) so Dockerfile errors are caught; keep the existing jobs green.
6. Write docs/dev/reports/cloud_deploy.md (files, how to deploy in 10 commands, validation done, what could not be validated here, changes needed in code owned by others).
