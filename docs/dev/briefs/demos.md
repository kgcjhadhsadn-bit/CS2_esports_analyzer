# P3 - Demo download, extraction, parsing (demoparser2), persistence and aggregates (cs2bot.ingest.demos)

> Work-package brief: the requirements this package was built against. Keep it in sync when scope changes.

**Owned paths:** src/cs2bot/ingest/demos/, tests/ingest/demos/

**Tests:** tests/ingest/demos/

## Requirements

Goal: turn HLTV demo archives into round/kill/economy/utility/position data so the models know who plays which position against whom, side strengths, economy conversion, trade rates, etc. Raw demos are big: download, parse, then delete (settings.demos.keep_archives / keep_dem_files).

1. Research demoparser2 (github.com/LaihoE/demoparser - README, python docs/examples, list of events and player props; the installed version is in .venv). Key API: DemoParser(path).parse_header(), parse_event(name, player=[...], other=[...]), parse_events([...]), parse_ticks([props], ticks=[...]), parse_player_info(), list_game_events(). Relevant events: round_start, round_freeze_end, round_end (winner, reason), round_officially_ended, player_death (attacker_steamid, user_steamid, assister_steamid, weapon, headshot, penetrated, thrusmoke, noscope, attackerblind, assistedflash, ...), player_hurt (dmg_health, weapon), bomb_planted/bomb_defused/bomb_exploded (site), player_blind, flashbang_detonate, smokegrenade_detonate, hegrenade_detonate, inferno_startburn, item_purchase. Useful props: X, Y, Z, last_place_name, team_num, team clan name, is_alive, health, current_equip_value, balance, total_rounds_played, is_warmup_period, match restart indicators. Also study how awpy (github.com/pnxenopoulos/awpy) cleans rounds (warmup, knife round, restarts, technical pauses) and classifies buys.
2. Downloader protocol: download_demo(url, dest_dir, *, downloader: Callable[[str, Path], Path] | None = None, timeout_s) -> Path. Default: httpx streaming download (follow redirects, size limit, temp file then atomic rename). The integration layer will pass a browser-based downloader for HLTV, so keep it injectable.
3. extract_archive(path, dest_dir) -> list[Path]: .rar (rarfile; the backend tools unar/bsdtar are installed here; on Windows the owner must install one - detect and raise a clear error if none is available), .zip, .zst/.gz single files, plain .dem passthrough. match_dem_files_to_maps(dem_paths, maps: list[tuple[int, str]], header_reader=...) -> dict[int, Path] using the demo header map_name ("de_mirage" -> "mirage") with filename hints (e.g. "-m1-", "mirage") to disambiguate; handle missing/extra files.
4. parse_demo(path, settings: DemoSettings, *, parser_factory=DemoParser) -> ParsedDemo (pandas DataFrames + metadata): map name, players (steamid, name, team clan name, side per round), and
   - rounds: number (real rounds only: drop warmup, knife round, rounds before the final match restart, duplicated rounds after technical restarts), winner side, end reason (map round_end reason codes to RoundEndReason), CT/T equipment value at freeze end, team money at round start, buy type per side (BuyType thresholds as module constants on per-player average equipment value; rounds 1 and 13 are PISTOL; overtime has no pistol round), bomb planted + site, survivors per side, duration;
   - kills: round, tick, seconds into round, attacker/victim/assister steamids, sides, weapon, headshot/penetrated/through_smoke/noscope/attacker_blind/flash_assisted, attacker/victim place (last_place_name) and coordinates, distance, is_opening (first kill of the round), is_trade (the attacker avenged a teammate killed by this victim within settings.trade_window_s), was_traded (this victim was avenged within the window);
   - player_rounds: kills, deaths, assists, damage dealt (capped at 100 per victim per round, no team damage), utility damage (HE + molotov/incendiary), enemies flashed, flashes/smokes/HE/molotovs thrown, equipment value, money at start, survived, KAST flag (kill, assist, survived or traded), opening kill/death, clutch situation (1vN for the last alive player of a side) and whether it was won;
   - position samples: for each alive player at each settings.position_sample_seconds offset after freeze end: place, x, y, z.
5. persist_parsed_demo(session, map_played_id, parsed, steamid_to_player_id: dict[int, int]) -> int: replace (idempotently) Round, Kill, PlayerRoundStats, PlayerPositionSample rows for that map; derive team1_side per round from which side the match's team1 players were on; unknown steamids -> None player ids (never fail). resolve_steamids(session, match_id, parsed) -> dict[int, int]: use Player.extra["steamid"] when known, else match demo names to the match lineup nicknames (utils.names.normalize_player_name, fuzzy fallback) and store the steamid in Player.extra (assign a NEW dict so SQLAlchemy detects the JSON change).
6. process_pending_demos(session_factory, settings: Settings, *, downloader=None, parser_factory=DemoParser, limit: int = 5) -> ProcessReport: select Demo rows with status PENDING (or FAILED with attempts < 3), mark DOWNLOADING, download, extract, map dem files to the match's MapPlayed rows, parse + persist each map, mark PARSED (parser_version = demoparser2 version) or FAILED with error, increment attempts, delete raw files unless the keep flags are set. One bad demo never stops the batch.
7. aggregates.py: rebuild_position_aggregates(session, *, window_days=120, sample_second=20, as_of: date | None = None) and rebuild_duel_aggregates(session, *, window_days=120, as_of=None) writing PositionAggregate (per player/map/side/place: rounds sampled, presence share, kills/deaths/opening kills/deaths at that place) and DuelAggregate (attacker vs victim counts per map plus map_name "*"), replacing rows for the same window_end.
8. Tests (no real demo file is available): build pandas DataFrames shaped exactly like demoparser2 outputs and inject a fake parser via parser_factory; test round cleaning (warmup, knife, restart duplicates), reason mapping, buy classification incl. pistol/OT, trade/was_traded logic at the window boundary, damage capping, KAST, clutch detection, position sampling, persistence orientation + idempotency (run twice), steamid resolution, archive extraction (zip, zst, plain dem; rar via a mocked rarfile), the pending pipeline with fakes (success + failure + retry count + file deletion), aggregates.
