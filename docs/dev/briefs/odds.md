# P4 - Betclic odds collection, market mapping, event linking, quotes (cs2bot.odds)

> Work-package brief: the requirements this package was built against. Keep it in sync when scope changes.

**Owned paths:** src/cs2bot/odds/, config/betclic_markets.yaml, tests/odds/

**Tests:** tests/odds/

## Requirements

Goal: collect every pre-match CS2 market Betclic.pl offers, store price history (only on change), link each Betclic event to our match (with team-order swap detection), and map each market/selection into our taxonomy (cs2bot.domain.markets) so it can be priced. Betclic.pl only serves Polish IPs, so nothing can be verified live from here: the design must be data-driven and tolerant, and must save raw payloads so the parser/rules can be fitted on the owner's PC. Odds collection does NOT log in (prices are public) and must use a separate, non-persistent browser context (the logged-in profile belongs to the executor).

1. Research how Betclic's web apps load odds (open-source scrapers on GitHub mentioning betclic / begmedia / "offering" / sitecode=plpl; historically JSON from hosts like offering.begmedia.com or offer.cdn.betclic.* with params application/countrycode/language/sitecode; the site may embed Angular transfer state in a <script type="application/json"> tag). Document what you learn in the module docstring.
2. Sources (OddsSource protocol: fetch_cs2_events() -> list[CollectedEvent]):
   - BetclicBrowserSource(settings): Playwright (headless per settings.betclic.headless, executable_path from settings.betclic.chromium_executable, locale pl-PL, timezone Europe/Warsaw, optional proxy) opens settings.betclic.base_url + cs2_listing_path, follows links to each CS2 event page, captures every JSON network response (page.on("response")) and embedded JSON state, saves raw payloads under settings.data_dir / "raw" / "betclic" / <UTC date> / ..., then parses them. Polite pacing between pages. Event pages must be visited to get the full market list (listing pages usually show only the match winner).
   - BetclicApiSource(settings, http_client=None): optional direct JSON fetch when settings.betclic.offering_api_base is set (endpoint templates configurable).
   - payload_parser.extract_events(payloads: Iterable[Any], *, source_url=None) -> list[CollectedEvent]: a generic recursive walker that recognises event-like objects (id + name/contestants + start date + markets) and market-like objects (name + selections with decimal odds), with configurable key-name candidates (id/eventId/matchId, name/label, contestants/competitors/teams/opponents, date/startDate/matchDateUtc, markets/marketGroups/bets, selections/outcomes/choices, odds/price/odd/oddValue). Parse decimal odds given as numbers or Polish strings ("1,85"). Merge duplicates of the same event found in several payloads. Unit-test it against several plausible payload shapes (one modelled on the historic begmedia offering API, one Angular-transfer-state-like, one flat).
3. market_mapping.MarketMapper.from_yaml(path) with rules in config/betclic_markets.yaml (ordered regex rules over normalised Polish AND English market names -> MarketType + parameter extraction): match winner ("Zwycięzca meczu", "Wynik meczu", "Kto wygra"), map winner ("Zwycięzca mapy 1", "1. mapa - zwycięzca", "Mapa 2"), correct map score ("Dokładny wynik", scores like "2:1"/"2-1"), map handicap ("Handicap map" with selections like "Team (-1.5)"), total maps ("Liczba map" with "Powyżej/Poniżej 2.5"), both teams win a map, round handicap per map ("Handicap rund - mapa 1"), total rounds per map ("Liczba rund - mapa 1", "Suma rund"), team total rounds, odd/even rounds ("Parzysta/Nieparzysta"), map exact score, overtime ("Dogrywka - mapa 1" Tak/Nie), pistol round winner ("Runda pistoletowa", "1. runda", "13. runda"), race to N rounds ("Pierwszy do 5 rund"), half winner ("1. połowa"), player kills ("Zabójstwa gracza", "Liczba zabójstw - <nick>"), player head-to-head kills, top fragger ("Najwięcej zabójstw"). Lines are parsed from market or selection names with comma/dot decimals. Selections map to keys in OUR orientation: team selections are identified by fuzzy-matching the selection text against the event's team1_raw/team2_raw (utils.names.team_name_similarity) or "1"/"2"/"X", then flipped if the event is swapped (bookmaker team1 == our team2). Handicap lines are normalised to team1's perspective exactly as documented in cs2bot/domain/markets.py (spec.line is team1's handicap; a "Team2 -1.5" selection becomes spec line +1.5 with selection "team2" - document and test the rule). Player names are mapped to internal player ids via an injected resolver (nickname -> player id among the match lineups); unknown players -> unmapped. map(market_raw, selection_raw, *, event: CollectedEvent, swapped: bool, player_resolver=None) -> MappedSelection | None. Unknown markets return None (stored unmapped). Because Betclic's exact Polish naming is unverified, make the YAML easy to extend and provide list_unmapped(session) -> list[tuple[str, int]] (raw market names never mapped, with counts) for tuning.
4. event_matching.link_event(session, event_row: BookmakerEvent, *, settings: Settings, now) -> LinkResult: candidates = matches (status scheduled/live, preferring in_scope) whose scheduled_at is within +-12 h of starts_at (or the same local day if missing); score = team-name similarity in both orientations (against Team.name and TeamAlias aliases) + time proximity + competition similarity; pick the best, set teams_swapped, link_confidence in [0, 1], link_status AUTO when confidence >= settings.decision.min_event_link_confidence and clearly ahead of the runner-up, else PENDING_REVIEW; never override CONFIRMED or REJECTED rows (manual decisions from the dashboard). Store Betclic raw team names as TeamAlias(source=BETCLIC) when the link is AUTO/CONFIRMED to speed up future links.
5. collector.collect_once(session, source, mapper, *, settings: Settings, now=None, player_resolver_factory=None) -> CollectReport: upsert BookmakerEvent / BookmakerMarket / BookmakerSelection (natural keys per the unique constraints), (re)link events, (re)map markets & selections (re-map whenever the link or swap flag changes), write OddsSnapshot ONLY when odds or availability changed vs selection.last_odds/is_available, update last_odds/last_odds_at/last_seen_at, mark selections of a market that disappeared from a refreshed event as unavailable (snapshot the change), record raw payload paths in event.extra. Live events (is_live) are stored but flagged (pre-match only system).
6. quotes.latest_quotes(session, match_id, *, max_age_s, now) -> list[OddsQuote]: mapped + available selections of AUTO/CONFIRMED-linked, non-live events with fresh odds; closing_odds(session, selection_id, kickoff) -> Decimal | None (last snapshot strictly before kickoff); odds_history(session, selection_id) -> list[tuple[datetime, Decimal, bool]].
7. Tests: payload parser (3+ shapes, Polish decimals, duplicates merged), table-driven mapping tests (>= 40 cases incl. swapped events, handicap normalisation, Polish/English names, player markets with a fake resolver, unknown markets), linking (exact, alias, swapped, ambiguous -> PENDING_REVIEW, manual statuses preserved), collector (first run inserts, a second identical run writes no snapshots, a price change writes one, a disappearing selection -> unavailable snapshot, relink re-maps), quotes freshness/live filtering, browser source against a local page that fires XHR JSON (page.route; mark browser).

## Addendum (after the first build wave)

- Foundation additions available: `CollectedEvent.captured_at` / `sport_raw`, `BookmakerSelection.last_seen_at`, `BookmakerMarket.extra`. Use them instead of the workarounds (`last_odds_at` should mean "price last confirmed at"; keep the freshness semantics of `latest_quotes` correct and tested).
- `BetclicSettings.h2h_tie_rule` and `totals_include_overtime` hold the settlement-rule assumptions the pricing engine uses; if a Betclic market name states otherwise (e.g. "bez dogrywki" / "regulaminowy czas"), such markets must NOT be mapped onto the standard spec (leave them unmapped or encode the difference) - check the rules file for this.
- The API's link review sets `event.extra["remap_required"]` after a manual confirm/reject/relink (docs/dev/reports/api.md); make sure the collector honours it.
