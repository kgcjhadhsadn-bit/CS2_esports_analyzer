# P7a - Datasets and features: DB -> records, leakage-safe features, roles, meta/patches/change points (cs2bot.datasets, cs2bot.features)

> Work-package brief: the requirements this package was built against. Keep it in sync when scope changes.

**Owned paths:** src/cs2bot/datasets/, src/cs2bot/features/, config/patches.yaml, tests/learning/

**Tests:** tests/learning/

## Requirements

1. cs2bot.datasets (DB -> records, chronological, in-scope by default): load_map_results(session, *, since=None, until=None, in_scope_only=True) -> list[MapResultRecord] (finished maps with scores; team1/team2 orientation from matches; picked_by from picked_by_team_id/is_decider; side splits; overtime rounds; lineups from match_lineups; is_lan/tier/format from match/tournament), load_veto_records(...) -> list[VetoRecord], load_round_records(...) -> list[RoundRecord] (rounds joined to maps/matches, converted to team1 orientation: buy types/equipment/money/survivors by team1_side; score before each round computed cumulatively), load_player_map_records(...) -> list[PlayerMapRecord] (player_map_stats with source preference DEMO > HLTV > PANDASCORE > SYNTHETIC when duplicated; opponent team; role from players.primary_role; stand-in flag from match_lineups; awp_kills if available). DataFrame helper to_frame(records) (pandas). Everything must work on SQLite (tests) and PostgreSQL.
2. cs2bot.features - leakage-safe feature engineering. Every function takes an as_of timestamp and may only use data strictly before it. Build a FeatureStore (or equivalent) that precomputes chronological indexes so computing features for thousands of training rows is fast. Features per (match, map, team1-vs-team2): form (rolling win rate and round differential over 30/90 days, overall and on this map), opponent-adjusted form (e.g. average round-share residual vs an opponent-strength proxy), head-to-head, days since last match, matches in the last 14 days, roster continuity (share of the current lineup that played together in the last N maps), days since the last roster change, stand-in present, LAN, tier, map pick indicator (team picked this map / decider), map pool depth, side strengths (CT/T round win% per map), player aggregates over recent maps (rating, KPR, ADR, opening duel win%, AWP kill share, KAST) and demo-derived aggregates when those tables have data (trade %, utility damage per round, post-plant/retake win %, eco/force conversion). Return a flat dict[str, float] with NaN for unavailable values (LightGBM handles NaN). Provide build_training_rows(map_results, *, store, rating_provider=None) -> (pandas.DataFrame X, numpy y, pandas meta DataFrame with match_id/map_number/map_name/as_of) and features_for_match_map(ctx: MatchContext, map_name, *, store, as_of, rating_provider=None) -> dict[str, float]. rating_provider is a typing.Protocol (define it in cs2bot.features) with predict(team1_id, team2_id, map_name, as_of, *, is_lan=False) -> MapWinEstimate (cs2bot.models.ratings.MapRatingModel, built in parallel by another engineer, will satisfy it); when given, include rating-based features (p, logit, sigma, component values).
3. features/roles.py - infer_roles(session or frames, *, window_days=120, as_of=None) -> dict[int, tuple[PlayerRole, float]] from demo data: AWP kill share -> AWPER; T-side opening duel attempt share -> ENTRY; CT position concentration on one site -> ANCHOR vs ROTATOR; T-side late-round kills / distance from teammates (position samples) -> LURKER; otherwise SUPPORT/RIFLER; IGL cannot be inferred (keep existing). update_player_roles(session, ...) writes players.primary_role/role_confidence only when the new confidence beats the stored one.
4. features/meta.py - detect_active_map_pool(map_results, as_of, *, window_days=60, min_share=0.04) -> list[str]; a patch timeline loaded from config/patches.yaml (research and list notable CS2 updates since 2023-09-27 with dates: release/MR12, Active Duty map pool changes, economy/weapon changes that shifted the meta; mark unverified dates clearly in the file) with days_since_last_patch(as_of) and patch_id(as_of); change-point detection on a team's performance series (Bayesian online change point detection (Adams & MacKay 2007) or CUSUM on round-share residuals) -> recent_regime_break(team_id, as_of) and form_trend(team_id, as_of).
5. Tests: on a SQLite DB populated with cs2bot.testing.synthetic.populate_db (with rounds and kills): loaders return correct counts and orientation; round score-before reconstruction; source preference; leakage test (features for a match never use that match or later ones - e.g. compare features computed with and without future records); speed sanity (thousands of rows in seconds); roles inference (synthetic kills carry no weapons - build a small handcrafted kills/positions fixture for weapon/position-based role tests); map pool detection; the patches file loads; change-point detection finds an injected break in a synthetic series.

## Addendum (after the first build wave)

- Foundation additions you must use: `PlayerMapRecord.team_rounds_won` / `opponent_rounds_won` (fill them), `rounds.source` (DEMO rows are complete; HLTV round-history rows only have winner/side/end reason and no buy types; SYNTHETIC rows are complete), `LineupPlayer.role`, `MatchContext.start_sides`.
- Two more loaders belong in `cs2bot.datasets` (the integration layer and the API need them):
  - `load_match_context(session, match_id, *, settings, now=None) -> MatchContext`: teams, tier, LAN, tournament/stage, lineups (match_lineups incl. stand-ins and `players.primary_role`; fall back to each team's most recent lineup when the match has none yet), `map_pool` (features.meta.detect_active_map_pool, falling back to `settings.scope.active_map_pool`), `known_veto` (vetoes table in team1/team2 orientation), `start_sides` (from `maps_played.team1_start_side` when already known), `first_veto_team` when inferable from the first veto step. Also `data_completeness(session, ctx) -> float` in [0, 1] (documented weights: both lineups known with 5 players, enough recent maps per team, veto history, player stats, odds link) - it gates betting (`decision.min_data_completeness`).
  - `load_match_actuals(session, match_id) -> MatchActuals | None` (see `cs2bot.domain.results`): maps actually played with scores, `round_winners` from the rounds table when every round is present, `player_kills` per map (same source preference as the player records), `forfeited` (HLTV stores forfeits in `Match.extra["hltv"]`; read docs/dev/reports/hltv.md), `cancelled`, `complete`.
- `cs2bot.models.ratings.MapRatingModel` is being finished in parallel; code against the Protocol only.
