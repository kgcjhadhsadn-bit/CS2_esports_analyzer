# Cloud autonomy: auto-login, auto-resume, circuit breaker, Telegram

**Owned paths:** you run alongside ONE other engineer (cloud_deploy, who owns `deploy/linux/`, `Dockerfile*`, `docker-compose.cloud.yml`, `Caddyfile`, `docs/VPS_SETUP.md`, `.github/workflows/`). Everything else in the repository is yours to edit, including foundation files (config, domain, db + an Alembic migration if needed), `services/`, `flows/`, `executor/`, `api/`, `dashboard/`, `cli.py` and docs other than `docs/VPS_SETUP.md`.

**Tests:** tests/services/ (new files prefixed `test_autonomy_` / `test_telegram_`), plus tests next to any package you change.

## Context

PLAN.md section 0 / 0b (read it): the bot now runs on a Polish VPS with **no human interaction**. Decisions: saved Betclic password is auto-filled AND submitted; no SMS/2FA automation (never implement code interception or 2FA bypass); **every automatic pause auto-resumes** once its cause is resolved; the **kill switch never auto-resumes** (owner-only); notifications and control via **Telegram**.

## Requirements

1. **Settings** (`config.py`): an `autonomy` section (`enabled`, `auto_login`, `auto_resume` policy, circuit-breaker window/limit, login retry interval) and a `telegram` section (`enabled`, `bot_token: OptionalSecret`, `chat_id`, `daily_report_time` Warsaw, which events to send). `.env.example` updated. Defaults safe for tests (disabled unless configured).
2. **Auto-login** (`executor`): when the session is logged out and credentials are configured (`credentials_source` env/keyring) and `autonomy.auto_login`, fill AND submit the login form; detect the 2FA / SMS step and stop there (status "2fa_required", Telegram alert, stay paused, retry later); detect wrong-password / account-locked messages and stop retrying (alert). Never log credentials. Selectors in `config/betclic_selectors.yaml`. Browser tests against the mock site (extend it with a login form, a 2FA step and an error).
3. **Pause reasons as structured data**: every automatic pause records a machine-readable reason (`loss_limit_daily`, `loss_limit_weekly`, `uncertain_bet`, `login_required`, `2fa_required`, `balance_mismatch`, `selector_error`, `executor_unavailable`, ...) with its time in `system_state`, alongside the human text. Manual pauses (dashboard / Telegram / CLI) are `manual`.
4. **Auto-resume service** (`services/autonomy.py`, a scheduler job every few minutes): for each reason, check whether the cause is resolved and resume: daily loss limit -> next Warsaw midnight; weekly -> next Monday 00:00 Warsaw; uncertain bet -> resolved by reconciliation against Betclic history; login/2FA -> a successful auto-login or a logged-in health check; balance mismatch -> book a RECONCILIATION/ADJUSTMENT ledger entry for the difference (the user chose "auto-resume everything") and resume; selector/executor errors -> a passing executor health check. **Never clear the kill switch, never resume a manual pause.** Circuit breaker: if the same reason auto-resumes more than N times in the window (configurable, e.g. 3 in 24 h), stay paused, mark `circuit_open`, and alert. Every auto-resume is written to `audit_log` and sent to Telegram.
5. **Telegram** (`services/telegram.py` + scheduler job): send-only client via httpx to the Bot API (`sendMessage`), rate-limited, retries, never raising into the betting path. Messages: each placed bet (match, market, selection, odds, stake, p, EV), settlements, daily P&L report at the configured time, every pause/resume/circuit-open, errors, startup/shutdown. Commands via long-polling `getUpdates` (only from the configured `chat_id`; everything else ignored and logged): `/status`, `/balance`, `/bets`, `/pause`, `/resume` (lifts a pause, never the kill switch... except see /go), `/stop` (kill switch ON), `/go` (kill switch OFF - the owner's explicit action), `/help`. Bot token is a secret. Tests with respx.
6. **Wire into `flows/jobs.py` / `flows/supervisor.py`**: the autonomy job and the Telegram poller run in the scheduler; startup and shutdown notifications; `cs2bot doctor` checks the Telegram token/chat and the credentials when auto-login is on. CLI: `cs2bot telegram test` (send a test message), `cs2bot control status`.
7. **Headless/server robustness**: the executor and odds browser must work on a Linux server without a desktop (headful under Xvfb via `DISPLAY`, or headless) - make it a setting, document which the VPS uses. A crashed browser is recreated by the worker on the next job.
8. **Dashboard/API**: show the structured pause reason, auto-resume ETA, circuit-breaker state and Telegram status on the overview/health pages.
9. Docs: update docs/OPERATIONS.md (autonomous operation, what each alert means, the two cases that still need the owner), docs/ARCHITECTURE.md, README.md, CLAUDE.md where relevant; write docs/dev/reports/cloud_autonomy.md.
10. Definition of done: the WHOLE suite passes (`.venv/bin/python -m pytest tests -q -n 2`), ruff, ruff format --check and mypy clean, dashboard `npm run lint && npm test && npm run build` pass if you changed it.
