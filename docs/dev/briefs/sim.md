# P6 - Round model, economy map simulator, player kill props, match engine (cs2bot.models.economy / round_model / map_sim / player_props / match_engine)

> Work-package brief: the requirements this package was built against. Keep it in sync when scope changes.

**Owned paths:** src/cs2bot/models/economy.py, src/cs2bot/models/round_model.py, src/cs2bot/models/map_sim.py, src/cs2bot/models/player_props.py, src/cs2bot/models/match_engine.py (helpers allowed as src/cs2bot/models/sim_*.py), tests/models/sim/

**Tests:** tests/models/sim/

## Requirements

Goal: from per-map win probabilities (supplied by the rating/ensemble layer as MapWinEstimate) and a veto distribution (list[MapSequenceProbability]), produce a MatchPrediction (cs2bot.domain.predictions - read its docstring carefully) with full distributions for every market: match/map winners, map scores, round handicaps/totals, overtime, pistol rounds, halves, race-to-N, player kills, top fragger.

1. economy.py - EconomyParams with researched CS2 values (verify with current sources, e.g. Liquipedia "Counter-Strike 2" economy pages, Valve patch notes, competitive game-mode configs; document each value and its source in comments): MR12 regulation (first to 13, side swap after round 12), overtime MR3 (6 rounds, first to 4 within the overtime, repeat at 3-3; verify which sides teams take at the start of overtime and at the OT half), start money 800, max money 16000, round-win rewards (elimination / time / defuse / detonation), loss bonus ladder 1400..3400 with CS2 semantics (starting loss count, decrement-on-win), bomb plant bonus to Terrorists, approximate per-kill rewards, overtime start money (verify the professional value). All configurable.
2. round_model.py - RoundModel: P(team A wins a round | A's side, buy matchup (BuyType A vs B), map, strength difference d). Logistic form with per-map CT bias, a buy-matchup effects table, and d. fit(rounds: Iterable[RoundRecord]) estimates the CT bias per map and buy effects (regularised toward priors from public knowledge: e.g. full buy vs eco ~85-90%, pistol rounds ~50/50 +- side bias, CT round win rate per map roughly 45-58%); handles thin data. round_win_prob(...) vectorised (numpy arrays). save/load.
3. map_sim.py - MapSimInput (map_name, strength_diff d, team1_start_side or None for unknown, economy params, round model) and MapSimulator.simulate(inp, n_sims, rng) -> MapSimOutput, VECTORISED over simulations with numpy (target: 20k sims of one map well under 1 second): per round, team money states -> buy decisions (team-level policy: pistol rounds; full buy when affordable; probabilistic force/eco logic depending on money, loss streak and round importance; carry-over value for surviving winners), outcome via RoundModel, survivors approximation, economy updates, side swaps, regulation end at 13, overtime rules. Unknown starting side -> 50/50 mixture. Output: score_pmf ("13-9" -> p incl. overtime scores), p_team1_win, p_overtime, p_team1_pistol {"1": .., "13": ..}, p_team1_half {"1","2"} and p_half_draw (half = rounds 1-12 / 13-24; 6-6 is a draw), p_team1_race_to {"3","5","10"...configurable} plus p_neither_race_to when relevant, and arrays per simulation (team1_rounds, team2_rounds, total rounds) for player props.
   calibrate_strength(target_p, inp, *, n_sims, rng_seed, tol=0.003) -> float: find d so the simulated P(team1 wins the map) matches target_p (bisection/secant with common random numbers; monotone in d), with caching.
4. player_props.py - PlayerKillModel: fit(records: Iterable[PlayerMapRecord], *, half_life_days=120) estimating each player's kills per round with empirical-Bayes shrinkage toward a role prior (or team/global prior), an opponent defensive adjustment (opponent's deaths allowed per round vs average), a map adjustment, and a negative-binomial dispersion per role (method of moments). project(player_id, team: TeamSlot, map_name, opponent_team_id, rounds_pmf: dict[int, float] | numpy array of simulated rounds, *, as_of, nickname=None, role=None) -> PlayerProjection (kills pmf as an NB mixture over the rounds distribution, mean, var). Optional team-level normalisation so a team's expected kills are consistent with expected opponent deaths. top_fragger_probs(...) -> dict[str, float] by joint simulation (ties split evenly). Unknown players -> role/global prior with wider dispersion. save/load.
5. match_engine.py - build_match_prediction(*, match_id: int, fmt: MatchFormat, team1_id: int, team2_id: int, veto_distribution: list[MapSequenceProbability], map_estimates: dict[str, MapWinEstimate], round_model: RoundModel, economy: EconomyParams | None = None, start_sides: dict[str, Side | None] | None = None, players: list[PlayerInput] | None = None, kill_model: PlayerKillModel | None = None, logit_shift: float = 0.0, context_flags: Sequence[ContextFlag] = (), n_sims: int = 20000, seed: int | None = None, model_version: str, data_completeness: float = 0.0, veto_known: bool = False, created_at: datetime | None = None) -> MatchPrediction. Steps: apply logit_shift to every map's p; build scenarios central / low / high where low/high shift each map's logit by -/+ sigma_logit = sigma / (p (1 - p)) (perfectly correlated across maps); per scenario and map: calibrate_strength -> simulate (cache per (map, rounded p)); series math EXACTLY: for each veto sequence (probability q) and map outcomes, compute the series result distribution; slot k is played iff the series is still undecided before map k (BO3 map 3 only at 1-1; BO5 maps 4/5 conditional; BO1 slot 1 always; BO2 both maps, draw possible); MapSlotPrediction.p_played, map_distribution (conditional on played), p_team1_win and all distributions as mixtures conditional on the slot being played; PredictionCore.map_score_pmf ("2-1" etc.; BO2 "1-1" = draw with p_draw), p_team1_win; player kills per slot ("map:k"), per "maps:1,2" (sum of slot 1 and slot 2 kills, independence given the scenario) and per "match" (sum over played maps; mixture over the number of maps); top fragger per scope. sigma_team1_win = |p_high - p_low| / 2. Fill components (per-map d values, cache stats, timing). Keep the total runtime for a BO3 with 3 scenarios reasonable (< ~20 s at 20k sims; fewer sims for low/high are acceptable if documented).
6. Tests: MR12/OT termination and side-swap rules on the simulator; economy sanity (after a pistol loss the loser usually ecos round 2); calibrate_strength accuracy and monotonicity; the simulated total-rounds distribution vs the synthetic universe's empirical distribution for similar strength gaps (loose check); every pmf sums to 1; BO3 slot 3 p_played == P(1-1); BO1/BO2/BO5 handling; low < central < high for team1; player kill pmf mean ~ KPR x expected rounds; top fragger probabilities sum to 1 per scope; reproducibility with a seed; a performance smoke test (mark slow if > a few seconds).
