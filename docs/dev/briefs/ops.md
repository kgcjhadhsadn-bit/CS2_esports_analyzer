# P11 - Local install & operations on the owner's Windows PC (Docker Postgres, PowerShell, CI, docs)

**Tests:** (no Python tests required; validate files with commands)

## Requirements

Goal: make the system easy to install and run for a non-developer on a Windows 10/11 PC in Poland, fully local, as PLAN.md specifies: Docker Desktop runs ONLY PostgreSQL; the Python app runs natively via uv (so Playwright can open a visible browser for the Betclic login); the dashboard is served by the app at http://127.0.0.1:8000; one start command (cs2bot up - implemented later by the integration engineer; use the exact CLI names from the "CLI" table in docs/ARCHITECTURE.md); optional autostart via Windows Task Scheduler; the PC must be awake before matches.

Deliverables:
1. docker-compose.yml: postgres:16 (pin a specific minor tag), published as 127.0.0.1:5432:5432 only, named volume, healthcheck (pg_isready), POSTGRES_USER/POSTGRES_PASSWORD/POSTGRES_DB from the .env file with safe defaults that match CS2BOT_DATABASE__URL in .env.example (read it; mention if they disagree), restart unless-stopped, sensible shared_buffers/work_mem for a desktop, UTF8. Validate syntax with "docker compose config" (the docker CLI is installed here even though the daemon isn't running).
2. deploy/windows/*.ps1 (PowerShell 5.1 compatible, Set-StrictMode, clear messages, idempotent): install.ps1 (check/install prerequisites with winget where possible: Docker Desktop, Git, Node.js LTS; install uv via the official installer; create .env from .env.example if missing and open it for editing; uv sync; uv run playwright install chromium; docker compose up -d; wait for healthy; uv run cs2bot db upgrade; build the dashboard (npm ci; npm run build in dashboard/ when present); print next steps), start.ps1 (ensure Docker Desktop is running and Postgres healthy, then uv run cs2bot up; logs to logs/ with rotation), stop.ps1, betclic-login.ps1 (uv run cs2bot executor login), backup-db.ps1 (pg_dump via docker exec into backups/ with timestamp + retention), restore-db.ps1 (with a confirmation prompt), update.ps1 (git pull, uv sync, migrations, dashboard rebuild), register-autostart.ps1 / unregister-autostart.ps1 (Task Scheduler task at user logon running start.ps1 hidden, with restart-on-failure), power-settings.ps1 (optional: show/adjust powercfg so the PC doesn't sleep while the bot runs; explain trade-offs; never change settings without asking). Also scripts/*.sh equivalents for Linux/macOS developers (dev.sh to start postgres + app, test.sh).
3. docs/WINDOWS_SETUP.md: a step-by-step guide for a non-developer (explain what each step does): prerequisites, disk space (100-200 GB free for the database and temporary demo files; raw demos are deleted after parsing), cloning, filling .env (PandaScore token, Anthropic API key, bankroll and limits; never paste secrets into chat), first start, the first Betclic login in the bot's own browser window (incl. 2FA), checking the dashboard, the dry-run smoke test and how to set CS2BOT_EXECUTOR__DRY_RUN=false to go live (the owner chose to go live immediately - explain how, plus the risks: Betclic's ToS forbid bots so the account/balance is at risk, no system wins every bet, 18+, gamble responsibly, Polish tax), keeping the PC awake before matches, autostart, backups, updating, troubleshooting (Docker not running, port 5432 in use, Playwright browser missing, HLTV Cloudflare blocks (slow down / optional residential proxy for the backfill), Betclic selectors broken after a site update (edit config/betclic_selectors.yaml), login expired (bot pauses; log in again), unmapped markets (config/betclic_markets.yaml; cs2bot odds unmapped)).
4. docs/OPERATIONS.md: what runs when (scheduler jobs: odds every few minutes, upcoming sync, results sync, news, demo processing, predictions, betting, settlement, nightly retrain; catch-up after the PC was off), the safety controls (kill switch, pause, loss limits, dry run), daily routine, interpreting the dashboard, logs, backups/restore, tuning thresholds, recalibrating selectors and market rules, data retention.
5. .github/workflows/ci.yml: jobs (a) lint+type (ruff check, ruff format --check, mypy) with astral-sh/setup-uv; (b) tests on ubuntu-latest with a postgres:16 service (CS2BOT_TEST_DATABASE_URL set so postgres-marked tests run) and Playwright Chromium installed for browser-marked tests ("uv run playwright install --with-deps chromium"); (c) tests on windows-latest excluding the browser and postgres markers (Windows path/compat check); (d) dashboard build (Node LTS, npm ci, npm run lint, npm test, npm run build) - conditional on dashboard/package.json existing so CI passes before the dashboard lands. Use concurrency groups and caching. Validate YAML syntax locally (.venv/bin/python -c "import yaml; yaml.safe_load(open(...))").
6. README.md: rewrite as the project front page: what it does, the honest constraints (no guaranteed wins, ToS risk, 18+), an architecture summary with links (PLAN.md, docs/ARCHITECTURE.md, docs/WINDOWS_SETUP.md, docs/OPERATIONS.md, docs/API.md, docs/DASHBOARD.md), quick start (Windows), a CLI cheat sheet (the exact names from docs/ARCHITECTURE.md), development commands.
